# AI Guide Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `framer-export <url> --ai-guide` (and `framer-export ai-guide <export-dir>`) write `AGENTS.md`, `CLAUDE.md` and an `ai-guide/` folder into a Framer export so that Claude Code or agy, using the superpowers skills, can build a clean Next.js project from it one page per task.

**Architecture:** A new module `src/ai-guide/` reuses the existing capture, breakpoint merge, page-structure, collection, token and font code from `src/nextjs/` to build a `GuideSite` model, adds a load-timeline recorder and section crops, and renders Markdown documents, a superpowers plan and a compare script from that model. Renderers are pure functions (unit tested); the browser work lives in two small files (integration tested on the existing fixture). The rule-based converter is not changed.

**Tech Stack:** TypeScript (Node 20+, ESM), puppeteer, pngjs, pixelmatch, node:test via `tsx`.

**Spec:** `docs/superpowers/specs/2026-11-10-ai-conversion-kit-design.md`

## Global Constraints

- Exports without `--ai-guide` behave exactly as before; `--ai-guide` must not enable or affect the `--nextjs` converter.
- A failure in the guide step never fails the export: it writes `ai-guide/ERROR.md` and returns.
- The guide step never writes inside `nextjs-app/` and never modifies the HTML export.
- Reference widths: 1440 / 1024 / 390 (`CAPTURE_WIDTHS` in `src/nextjs/model.ts`); breakpoints in the plan's rules: `tablet` = max 1199px, `mobile` = max 809px.
- Generated project stack named in the docs: Next.js 16, React 19, Tailwind 4, motion, GSAP + ScrollTrigger, Lenis, `@next/mdx`, ESLint, Prettier.
- One task per page in `plan.md`: task 0 setup, task 1 shell, one task per regular page, one per CMS collection, a final review task.
- Paths written into Markdown use forward slashes, relative to the export folder.
- Templates are TypeScript string modules (`src/ai-guide/templates/*.ts`) so `tsup` bundles them; no runtime file reads from `src/`.
- Hover effects are documented from the site's captured hover CSS (exact values) rather than before/after frames (deviation from spec §5 agreed in the plan review; frames are kept for load and scroll).

## Review Focus

1. `--ai-guide` given alone must not turn on the Next.js converter nor make `parseNextjsFlags` throw (it consumes `--ai-*`). → test in Task 7.
2. Re-running the guide on an export where the user has ticked boxes in `ai-guide/plan.md` must not wipe that progress: write `ai-guide/plan.new.md` instead and say so. → test in Task 4 (`writePlanFile`).
3. A page whose structure has no detectable sections must still appear in `site.md`, get an outline with one section, and get its own task. → test in Task 1.
4. A guide-step crash (e.g. capture fails) leaves the export intact and writes `ai-guide/ERROR.md` with the error. → test in Task 7.
5. An element that never settles during the 6 s load window (spinner, marquee, ticking clock) is reported as `loop` or custom behaviour, not as a load animation with a bogus end state. → test in Task 3.

- [ ] **Step 3: Implement `src/ai-guide/motion.ts`**

`summarizeLoad`: per key, compare each sample's opacity/transform with the last sample. No difference anywhere → no entry. Text differs between samples → `custom`. Differs from the last value in any of the final 3 samples → `loop`. Otherwise `load`: `startMs` = first `t` where the value differs from the first sample (or the first sample's `t` when it already differs from the end), end = first `t` from which the value equals the final value, `durationMs` = end − start; `from`/`to` written as `opacity X` and the transform expressed through `parseTransform` (`translateY -120px`, `rotate -14°`, `scale 0.9`), joined with `, `; `frames` = `load/NNN–MMM` from `t / frameEveryMs`, three digits. Easing: `spring-like overshoot` when an intermediate value passes the final value, else `ease-out`. `motionFromNodes` maps `motion.kind`: `reveal`/`split-text` → `in-view`, `scroll` → `scroll` (values listed), `loader`/`cursor`/`smooth-scroll` → `custom` with a note; hover entries list the CSS properties and values.
