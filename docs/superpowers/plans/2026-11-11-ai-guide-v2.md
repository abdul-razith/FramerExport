# AI guide v2 (build from the export's own code) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The AI guide maps every section of every page to its exact export markup, CSS and Framer animation settings, labels what each screen width shows, splits sections correctly, and gives the AI a working per-section comparison with a 90% gate and a `create-next-app --src-dir` setup.

**Architecture:** New focused modules in `src/ai-guide/` read the export itself (HTML with parse5, inline CSS with a small rule parser, `scripts/vendor/*.mjs` by text scanning) and are joined per section in a new `section-ref.ts` that writes `sections/<NN>-<name>/{ref.md, markup*.html, styles.css, shot-*.png}`. `split.ts` replaces the flat section list; `plan.ts`, the templates and `compare.mjs` are rewritten for the new layout. `index.ts` wires it; build-then-swap and failure handling stay as in v1.

**Tech Stack:** TypeScript (Node 20+, ESM), puppeteer, parse5, prettier, pngjs, pixelmatch (all already dependencies), node:test via `tsx`.

**Spec:** `docs/superpowers/specs/2026-11-11-ai-guide-export-references-design.md`

## Global Constraints

- No new runtime dependency in FramerExport (parse5, prettier, pngjs, pixelmatch, puppeteer are already there).
- Normal exports and the `--nextjs` converter must not change; no existing module statically imports `src/ai-guide` (isolation test).
- The export folder is never modified, except `AGENTS.md`, `CLAUDE.md`, `ai-guide/`.
- Widths: desktop 1440 (`base`), tablet 1024, mobile 390. Tablet media = `max-width: 1199px`, mobile = `max-width: 809px` (Framer also writes `809.98px` and `min-width: 810px`; treat them as the same groups).
- Gate copy in the guide: "≥ 90% at 1440, 1024 and 390, at most 3 fix rounds".
- Setup command, verbatim: `npx create-next-app@latest nextjs-app --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --yes`; then `npm i motion gsap @gsap/react lenis @next/mdx @mdx-js/loader @mdx-js/react` and `npm i -D @types/mdx puppeteer pngjs pixelmatch`. No version pins.
- Next.js paths in the guide are under `src/`: `src/app`, `src/components/{layout,sections,ui,motion}`, `src/content`, `src/lib`.
- Section ids are two digits (`01`…); shell part ids are `S1`, `S2`…; the AI marks roots with `data-section="<id>"` and generated elements with `data-live`.
- Every extractor failure is local: it writes `not available: <reason>` into that part of `ref.md`.
- Tests: `npm test` (unit), `npm run test:nextjs` (integration, `tests/integration-nextjs/*.test.ts`). One known pre-existing failure: `provider-presentation.test.ts` CRLF hash.

## Review Focus

1. A page whose sections are not inside Framer `ssr-variant` copies at all (one copy for all widths) — one `markup.html`, all elements labelled `all`. Test in Task 3.
2. A section class that appears in no `scripts/vendor/*.mjs` (static section) — `ref.md` says "no Framer animation settings for this section", not an error. Test in Task 4.
3. An identifier reused in several scopes (`Pn` = timezone table and `Pn` = transition) — the animation-like definition wins. Test in Task 4.
4. A page with no wrapper and no overlays (plain sections under `body`) — splitter returns them unchanged. Test in Task 5.
5. `compare.mjs` run for a section id the build lacks — prints `not found`, still writes the rest, exit code 0. Test in Task 8.
